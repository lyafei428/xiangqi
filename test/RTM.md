# 需求—测试矩阵（RTM）

集成测试的唯一索引。每个业务故事一节，每个集成用例一行；行号在写用例标题前定死，用例标题按行号命名。断言只写用户能观察到的业务结果，不写内部实现。

## 对弈（需求 F1）

| 行 | 集成用例 | 业务结果 | 用户入口 | 需求 |
|---|---|---|---|---|
| F1-1 | 本地双人走完一局并判和 | 红黑轮流走子；8 着后出现三次重复，面板显示「和棋 · 三次重复局面」并锁盘；「新局」恢复红方走棋 | 打开页面，在棋盘上点选走子 | F1.1 |
| F1-2 | 同房走子同步与重连 | 两台设备同房看到同一局面；非法着法被拒绝；断线后带 token 重连恢复 | 打开页面 → 联机 | F1.2 |
| F1-3 | 本地计时与认输 | 红方时钟归零显示「黑方胜 · 超时」并锁盘；认输立刻结束 | 打开页面 → 对弈 | F1.4、F1.5 |
| F1-4 | 联机计时、认输与求和 | 双方看到同一时钟；归零判负；求和被接受判和；被拒后再次提议被拒，对方走一着后可再提议 | 打开页面 → 联机 | F1.4、F1.5 |
| F1-5 | 棋谱回放、导入导出与续局 | 终局后棋谱页列出该局；回放可停在任意一步；导出文件重新导入能完整回放；关页重开棋盘与时钟接上 | 打开页面 → 对弈 / 棋谱 | F1.6 |
| F1-6 | 第三人观战 | 第三台设备进同一房间只看不走，无认输与求和按钮；棋手离开后仍能看；第 11 台设备被拒 | 打开页面 → 联机 | F1.7 |
| F1-7 | 人机对战 | 选难度与阵营后走一着，机器在 2 秒内回一着并更新棋盘；思考中棋盘不可动；换难度后回子速度变化可见；终局后不再回子 | 打开页面 → 人机 | F1.3 |

用例实现：

- `test/integration/local-play.test.tsx`：F1-1、F1-3、F1-5 的续局。
- `test/online.test.ts` 与 `test/integration/online.test.tsx`：F1-2、F1-4、F1-6 的联机面。
- `test/room.test.ts`：F1-6 的房间层（八人上限与回收）。
- `test/integration/replay.test.tsx`：F1-5 的列表、回放与导入导出。
- `test/ai.test.ts`、`test/ai-engine.test.ts` 与 `test/integration/ai.test.tsx`：F1-7。

## 响应式（需求 F4）

视口验收需要真实布局，jsdom 没有布局能力；这一节由浏览器实跑，用 CDP 驱本机浏览器取读数。

| 行 | 集成用例 | 业务结果 | 用户入口 | 需求 |
|---|---|---|---|---|
| F4-3 | 缩放不丢状态 | 视口从 1440 递减到 375 期间，着法记录、选中态、时钟不变；课程页步数不变 | 打开页面 → 对弈 / 课程 | F4.2 |
| F4-4 | 手机格宽下限 | 375 视口下棋盘完整可见，格宽不低于 40px | 打开页面 → 对弈（375 视口） | F4.3 |
| F4-5 | 触摸交互 | 点选能走子、拖动能走子；点「新局」棋盘重置、点「规则」换到规则页 | 打开页面 → 对弈 / 规则（触摸） | F4.4 |

用例实现：`scripts/acceptance.mjs`（复现：一个终端 `npm run preview`，另一个终端 `node scripts/acceptance.mjs`）。

## 性能（需求 F5）

首屏与走子流畅度是运行时读数，同样由浏览器实跑，口径见 `docs/design/acceptance.md`。

| 行 | 集成用例 | 业务结果 | 用户入口 | 需求 |
|---|---|---|---|---|
| F5-1 | 4G 快档首屏 | 首屏可交互时间低于 2 秒，请求不超过 6 个 | 打开页面 | F5.2 |
| F5-2 | 走子流畅 | 单步到画面 < 16ms；连走无掉帧 | 打开页面 → 对弈 | F5.3 |
| F5-3 | 布局稳定 | 加载期 CLS < 0.05；Lighthouse 手机档 Performance ≥ 90 | 打开页面 | F5.4 |

用例实现：`scripts/acceptance.mjs`；自证用 `node scripts/acceptance.mjs --self-test`。
