# 需求—测试矩阵（RTM）

集成测试的唯一索引。每个业务故事一节，每个集成用例一行；行号在写用例标题前定死，用例标题按行号命名。断言只写用户能观察到的业务结果，不写内部实现。

| 行 | 集成用例 | 业务结果 | 用户入口 | 需求 |
|---|---|---|---|---|

| 行 | 集成用例 | 业务结果 | 用户入口 | 需求 |
|---|---|---|---|---|
| F4-3 | 缩放不丢状态 | 视口从 1440 递减到 375 期间，着法记录、选中态、时钟不变；课程页步数不变 | 打开页面 → 对弈 / 课程 | F4.2 |
| F4-4 | 手机格宽下限 | 375 视口下格宽不低于 40px（棋盘完整可见归 F4-6） | 打开页面 → 对弈（375 视口） | F4.3 |
| F4-5 | 触摸交互 | 点选能走子、拖动能走子；点「新局」棋盘重置、点「规则」换到规则页；「着法」抽屉可展开与收起 | 打开页面 → 对弈 / 规则（触摸） | F4.4 |
| F4-6 | 小屏一屏装下棋盘 | 375×667 视口下棋盘第 10 行完整可见，页面无纵向滚动；展开「着法」后抽屉盖在棋盘上方，收起后棋盘恢复完整 | 打开页面 → 对弈（375×667 视口） | F4.6 |

## 性能（需求 F5）

首屏与走子流畅度是运行时读数，同样由浏览器实跑，口径见 `docs/design/acceptance.md`。

| 行 | 集成用例 | 业务结果 | 用户入口 | 需求 |
|---|---|---|---|---|
| F5-1 | 4G 快档首屏 | 首屏可交互时间低于 2 秒，请求不超过 6 个 | 打开页面 | F5.2 |
| F5-2 | 走子流畅 | 单步到画面 < 16ms；连走无掉帧 | 打开页面 → 对弈 | F5.3 |
| F5-3 | 布局稳定 | 加载期 CLS < 0.05；Lighthouse 手机档 Performance ≥ 90 | 打开页面 | F5.4 |
| F5-4 | 视觉基准与对比度 | 深浅两套界面可切换（跟随系统 / 浅色 / 深色）；棋盘两套下都是浅色；正文、次要文字、链接、按钮文字、双方文字与提示绿都看得清（对比度 ≥ 4.5:1）；界面上没有图片与渐变 | 打开页面（任意页） | F5.5 |
| F5-6 | 走子音效 | 落子 / 吃子 / 将军 / 终局四种声音可辨；静音开关生效且记住 | 打开页面 → 对弈 → 走子 / 认输 | F5.6 |
| F5-7 | 每步胜率 | 每一着后给出双方胜负概率；四个棋局页面都显示；有开关且记住 | 打开页面 → 对弈 → 走子 | F5.7 |
| F5-8 | 规则页进阶阅读 | 规则页判罚口径之下有「进阶阅读」一节，两篇长文默认收起；点开可见正文（每篇八节），正文不引用具体着法编号 | 打开页面 → 规则 → 点开第一篇 | F5.8 |

用例实现：`scripts/acceptance.mjs`（F5-1…F5-7）；自证用 `node scripts/acceptance.mjs --self-test`。F5-8 的实现在 `test/integration/rules.test.tsx`（两篇默认收起、正文各八节）与 `test/rules-content.test.ts`（常量与「正文不含着法编号」）。

F5-6 另有一条集成用例 `test/integration/sound.test.tsx`（对弈页真走一着 + 认输，数振荡器起振次数；关掉后不响且跨重挂仍是关）。
F5-7 另有一条集成用例 `test/integration/eval.test.tsx`（对弈页走两着看逐格百分比与条上的数字一致，关掉开关后两者都不渲染且重开仍是关；联机页收到快照、回放页游标到终局各一条最小观察）。
