# 走子音效

对局里四种可辨的声音：落子、吃子、将军、终局。声音现场合成，不引音频文件；带一枚静音开关，选择记住。

Closest precedent: `docs/design/modules/local-play.md` §4（`session` 的着法记录结构）与 `docs/design/modules/theme.md` §2（顶栏控件样式）。
对齐：沿用 `session.history` 的 `HistoryEntry` 作为唯一事件源，不另立一套「刚走了什么」的状态；开关沿用顶栏按钮基元与 `--radius-pill`。
偏离：本模块是唯一会主动发声的部分，前几批的界面全是静默的——所以要一条明确的边界：声音不进业务状态、不影响胜负与记录。

Survey evidence: 已核对 `docs/design/modules/local-play.md`（事件源）、`docs/design/modules/theme.md`（顶栏控件与设置浮层的既有归属）、`docs/requirements/xiangqi.md` F5.2 与 F5.6（请求数预算、音效验收口径）。相关：`HistoryEntry` 的字段、顶栏按钮基元、设置浮层的既有结构三处被沿用；其余来源与本题无关。

## 1. 为什么合成而不放音频

需求 F5.2 卡着「请求数 ≤ 6」，现在正好 6 条；四段音频就是四条请求，还要进 service worker 的预缓存清单。合成零请求、零体积、离线天然可用。

代价是音色朴素。要换成录制的木质落子声，只改 `src/client/sound/sound.ts` 里的 `VOICES` 与播放实现，接线（`classify` 与 `useGameSound`）不动。

## 2. 四个声音

| 事件 | 波形 | 频率与时长 | 增益 | 听感 |
|---|---|---|---|---|
| 落子 | 三角波 | 660→440Hz，60ms | 0.26 | 短促的「嗒」 |
| 吃子 | 方波 | 240→180Hz，110ms | 0.16 | 更低更硬的「啪」 |
| 将军 | 正弦波 | 660Hz 90ms + 990Hz 110ms，第二音压后 100ms | 0.12 / 0.12 | 上行「叮—叮」 |
| 终局 | 正弦波 | 523 / 659 / 784Hz 三音同按，400ms | 0.10 / 0.08 / 0.06 | 收束的「嗡」 |

音高按增益包络指数衰减到 0.0001 而不是线性归零：线性归零会在末尾「啪」一下，听起来像爆音。

**音量**：四种声音的增益就是它们的响度，取上表的值，不设用户可调的音量控件。理由两条——① 需求 F5.6 只要求「静音开关」，设备本体的音量键就是用户手上的那个旋钮，应用内再做一套是第二份音量，两处都调反而猜不到哪个生效；② 增益是合成参数，改它就是改音色本身，没有「只变响不变音」的干净切分。落子那一档的增益高于其余三音：它是每局听得最多的一下，被其它音盖住就失去提示作用。

## 3. 判定

`classify(entry, result)` 给出该响哪个，优先级：终局 > 将军 > 吃子 > 落子。

判据直接读 `HistoryEntry` 里的 `captured` 与 `gaveCheck`——这两个字段定义在 `src/shared/types.ts` 的 `HistoryEntry`（连同 `move` 与走完后的 `fen`），规则层走完那一着时就写下了，这里再拿局面比一遍就是第二份真相。

## 4. 接线

`useGameSound(session, enabled)` 只盯两个观测点：

**每份 session 各自挂一次**：对弈页的 session 在 `App`，人机页的在 `AiPage`——只在 `App` 挂过一次，人机页就永远没有声音（这就是「试听会响、走子不响」的根因）。开关用 `useSoundEnabled()` 这个共享 store 读，两处拿到的必然是同一个值。

- 结果从无到有 → 终局音；
- 着法数增加 → 按 `classify` 响**最后那一着**。

两条观测点互斥，终局优先：将死那一着同时满足「结果从无到有」与「着法数增加」，此时只响一次终局音（`classify` 也会把这一着判成终局），不再叠一声。

着法数一次增加多着（联机快照一次带回几着）时只按最后那一着响一次：中间那些是补传，不是刚刚发生在玩家眼前的动作。着法数不变、变少（新局、回退）都不响。AI 走子与联机快照走的是同一条路，因此不需要各写一遍。

## 5. 开关

顶栏右端一枚「设置」浮层（`<details>`），里面是配色下拉、「音效开 / 关」与「试听」。声音开关用 `aria-pressed` 表示状态，选择写 `localStorage`（`xiangqi.sound.v1`），缺省开——配置项必须有自己的界面写面。

浮层的**结构**不归本模块：它由 `docs/design/modules/theme.md` 的顶栏控件一节拥有（配色下拉就在那里），本模块只往浮层里追加两个控件，不改浮层的开合与位置。

**试听那一下顺手解掉了自动播放限制**：它是一次真实手势，点下去时 `prime()` 会把音频上下文点着并播一个静音样本；不然用户第一次听到的是「走子没声」，还以为功能坏了。

**为什么收进浮层**：七项导航 + 两个偏好挤在一行里，360px 的机器上开关会被顶出屏幕（用户报的「声音开关有被挤出」）。浮层只占一枚按钮的位置，任何宽度都放得下。

存储不可用（隐私模式）时按「开」处理，写失败不报错——与面板展开状态同一条失败路径，由 `test/prefs.test.ts` 覆盖。

## 6. 边界

- 不做音量滑杆（理由见 §2 的「音量」一段）、不做背景音乐、不做按材质分级的音色。
- 不做「对方走子单独音色」：人机与联机里谁走的，界面已经显示得够清楚。
- 任何发声失败都静默降级：没有 `AudioContext`、被自动播放策略拦（合成事件不产生用户激活，上下文停在 `suspended`）、设备静音，都当没听见处理。声音是可听反馈，不是业务结果，丢失不影响胜负与记录。

## 9. 验证

| 层 | 手段 |
|---|---|
| 判定正确 | `test/sound.test.ts`：用真实局面走出的 `HistoryEntry` 覆盖五条路径（普通落子、吃子、将军、终局压过一切、将死那一着只算终局） |
| 偏好读写 | `test/prefs.test.ts`：读回、坏值退缺省、存储抛错时不炸 |
| 改动面命令 | `node --test test/sound.test.ts test/prefs.test.ts` 与 `npx vitest run test/integration/sound.test.tsx`（提交前仍走 `npm run check` 整体闸门） |
| 人机页 | 浏览器探针在 `#/ai` 用触摸走一着：振荡器计数 +2（玩家一着 + AI 回一着），上下文 `running` |
| 真响了 | 浏览器探针记 `OscillatorNode.start` 与 `AudioContext.state`（集成用例数的是同一个量：终局是三音同按，所以「响一次终局」在计数上是 3，用例按这个口径断言）：**真实指针按下**（CDP Input，带用户激活）后上下文进 `running`、缓冲区计数 +1；随后走一着再 +1；关掉声音再走不增；重新打开后认输出现 3 个正弦波（终局三音，见 §2 的波形列）。用 `element.click()` 这类合成事件测不出来——它们不产生用户激活，上下文会一直停在 `suspended`，看起来「建了不响」 |

起点是 `test/RTM.md`：本变更落在 **F5-6 走子音效** 一行（「落子 / 吃子 / 将军 / 终局四种声音可辨；静音开关生效且记住」，入口「打开页面 → 对弈 → 走子 / 认输」，需求 F5.6）。

| 分类 | 结论 |
|---|---|
| 破坏 | 无：F5-6 此前没有实现，没有既有用例断言过声音 |
| 冗余 | 无：不复制 F1-1 / F1-3 的对局用例，声音只在该行验 |
| 缺失 | 一行：F5-6 的集成行——从对弈页真实走一着与一次认输，断言「落子响一次、终局响一次」与「关掉后不响、重开页面仍是关」；吃子与将军两条路径由 §9 的判定位用例覆盖（`test/sound.test.ts`），集成行不重复验判定 |

该行的断言只取业务可观察结果（响了几次、开关状态是否跨刷新保留），不取合成参数内部的节点细节；合成细节留给 `test/sound.test.ts`。
