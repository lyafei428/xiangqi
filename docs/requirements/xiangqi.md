# 中国象棋在线游戏 — 需求

## 1. 目标

一款可在浏览器、平板、手机上无缝使用的中国象棋应用，同时承担教学职责：不仅让人对弈，还要教会不懂规则的人下棋，并验证他确实学会了。

## 2. 用户与场景

| 用户 | 场景 | 关键诉求 |
|---|---|---|
| 初学者 | 第一次接触象棋，不懂走法 | 有讲解、有示范、能立即练 |
| 会下的人 | 想找人对弈或跟 AI 练 | 联机稳定、响应快、能复盘 |
| 手机用户 | 通勤路上看一课、下几手 | 单手可操作、不用放大 |

## 3. 功能需求

### F1 对弈

| 编号 | 需求 | 验收 |
|---|---|---|
| F1.1 | 本地双人同屏对弈 | 一台设备上红黑轮流走，能下完一局并判出结果 |
| F1.2 | 联机对战（房间码） | 两台设备进同一房间，走子实时同步 |
| F1.3 | 人机对战 | 可选难度，普通机器单步思考 ≤ 2 秒 |
| F1.4 | 计时对局：每方 10 分钟包干，走子后切给对方；己方归零判负 | 归零立刻判负并显示「超时」；从 1440 缩到 375，时钟不重置、不停表 |
| F1.5 | 认输与求和：行棋方随时可认输；任一方可提议和棋，对方接受即和、拒绝则继续；对方走一着前不能重复提议 | 认输后立刻结束并显示；求和被拒后能继续走子；重复提议被拒 |
| F1.6 | 棋谱存局：对局结束后可逐步回放；棋谱可导出与导入 JSON；本地对局关页重开后接着下 | 回放可走到任意一步；导出的 JSON 导入后能完整回放；重开后局面与时钟接上 |
| F1.7 | 观战：联机房间除两名棋手外可进观战者，只读同一局面，不参与走子与计时 | 第三人加入能看不能走；棋手离开不结束观战；观战上限 8 人 |
| F1.8 | 记谱输入：对弈页与人机页可在面板输入中文记谱直接走子 | 输入本方可走的记谱并回车，该步落到棋盘并进着法记录；输入看不懂的字符串不落子、给出提示；终局与 AI 回合输入框不可用；`/` 能聚焦输入框 |
| F1.9 | 棋谱库：开局 / 中局 / 终局 / 残局四类棋谱，可分类浏览与逐步回放 | 棋谱页能在「我的棋谱 / 棋谱库」间切换；四类各有 4 条且能按类筛选；点开任一棋谱可走到任意一步，棋盘与记谱同步，关键步的说明可见；内容自证测试全绿 |
| F1.10 | 对局专注：对弈页与人机页默认只显示棋盘、行棋方与双方计时、新局与认输 | 进入对局页看不到着法记录与记谱框；点「着法」后两者出现，再点收起；`/` 在收起态下先展开记谱区再聚焦输入框；人机页的难度与阵营在未走子时显示，选过之后鼠标移开就收为一行摘要（点摘要可再展开），新局重新铺开；走第一着后也收为一行摘要 |

### F2 教学

| 编号 | 需求 | 验收 |
|---|---|---|
| F2.1 | 分章课程，含讲解与棋盘演示 | 每课能读到讲解，并看到该走法在棋盘上走一遍 |
| F2.2 | v1 覆盖三章 22 课 | 走法 8 课、规则判罚 6 课、基本杀法 8 课，全部可跑通 |
| F2.3 | 每课局面经规则引擎验证 | 内容自证测试全绿，坏课不许存在 |

### F3 练习

| 编号 | 需求 | 验收 |
|---|---|---|
| F3.1 | 判定型练习（点选作答） | 走法题、合法性题、局面题、记谱题各可作答并判分 |
| F3.2 | 对弈型练习（棋盘上走） | 攻杀题、防守题、找杀题达成目标即通过 |
| F3.3 | 答案由引擎生成，不手写 | 题目答案 = 引擎输出，规则改一处，题库自动跟着对 |
| F3.4 | 答错有提示、有答案 | 错两次给提示，三次给答案并演示正确走法 |

### F4 响应式

| 编号 | 需求 | 验收 |
|---|---|---|
| F4.1 | 桌面 / 平板 / 手机同一套界面 | 三端不出现两套页面代码 |
| F4.2 | 切换过程不丢状态 | 窗口从 1440 连续缩到 375，局面、选中、计时、课程进度全部保留 |
| F4.3 | 棋盘格宽 ≥ 40 CSS px | 手机上不靠缩小棋盘迁就宽度 |
| F4.4 | 触屏与鼠标同一套交互 | 点选走子为主，拖动为辅；无 hover-only 交互 |
| F4.5 | 可添加到主屏全屏运行 | PWA manifest + 图标 |
| F4.6 | 小屏一屏装下棋盘 | 375×667 视口下棋盘第 10 行完整可见，页面无纵向滚动 |

### F5 简约与性能

| 编号 | 需求 | 验收 |
|---|---|---|
| F5.1 | 界面简约 | 每页只保留完成该页任务必需的控件；无装饰性元素 |
| F5.2 | 首屏快 | 手机 4G 快档首屏 < 2s，请求数 ≤ 6 |
| F5.3 | 走子流畅 | 走子到画面更新 < 16ms，连续走子无掉帧 |
| F5.4 | 布局稳定 | CLS < 0.05，Lighthouse 手机档 Performance ≥ 90 |
| F5.5 | 视觉基准 | 深色界面（近黑底、蓝色强调、描边分层）+ 浅色棋盘（棋子与盘线保持浅底可读）；正文、次要文字、链接与按钮文字的对比度均不低于 4.5:1；无装饰性图片与纹理、无渐变 |

## 4. 规则判罚口径

v1 采用简化判罚，并在规则页明示采用哪一版：

| 情形 | 判罚 |
|---|---|
| 将死（被将且无合法着法） | 被将方负 |
| 困毙（未被将但无合法着法） | 无着法方负 |
| 长将（同一方在重复循环中每着都将军） | 长将方负 |
| 三次重复局面 | 和 |
| 连续 60 回合（120 着）无吃子 | 和 |
| 超时（一方时钟归零） | 归零方负 |
| 认输 | 认输方负 |
| 一方提议和棋、对方接受 | 和 |

长捉、一将一闲等复杂判罚不在 v1 范围内，规则页写明。

## 5. 非目标

- 不做原生 App，PWA 足够。
- 不做付费、社交、好友关系链。
- 不做赛事编排、裁判后台。
- 不做国际象棋或其他棋种。
- v1 不做账号体系，进度存浏览器本地；跨设备同步留到后续批次。

## 6. 部署

v1 以本机开发运行为准（`npm run dev`）。公网部署需要反向代理与 WSS，作为独立批次补，不在 v1 验收内。
